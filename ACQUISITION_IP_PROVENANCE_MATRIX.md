## Dependency review notes

- Each package area uses `package-lock.json` lockfile format 3. The root packages are marked `UNLICENSED`/proprietary; this does not replace notices for third-party packages.
- No direct production dependency has a GPL-family licence recorded in the lockfile. The lockfiles do contain licence variants that merit inclusion in a full SBOM/NOTICE review: Hall Monitor's transitive `jszip` is `(MIT OR GPL-3.0-or-later)`; the client lock contains MPL-2.0 `lightningcss` platform packages; the website lock contains MPL-2.0 dependencies and Sharp platform packages with LGPL-3.0-or-later metadata. This is an inventory observation, not a licence interpretation.
- No vendor account, licence key, paid plan, or API credential is tracked. The optional Anthropic feature is technically disabled without a buyer-supplied environment key.

## Evidence limitations

1. The clean public history begins with the curated package and identifies a single Git author, but it does not include contributor agreements, source-creation history, design files, author affidavits, licence receipts, or chain-of-title records.
2. The controlled Drive folder contains CCRR, CEAM, CAGR, and CAIRE specification files and visual PNGs. File metadata/titles support their existence and internal relationship; it did not provide verified ownership or author-assignment evidence.
3. This review did not inspect untracked local files, prior clones/forks, external account administration, registrar records, or any excluded private archive.
4. The current repository is public. This matrix proposes a transaction and diligence boundary; it does not itself change the present distribution status of any tracked file.
